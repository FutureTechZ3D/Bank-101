## Batch 1 (2026-11-09): backend hardening, DONE
Health check: `cd backend && npm test` -> **45/45** (pg-mem running the REAL `database/schema.sql` + `seed.sql` + `migrations/001_hardening.sql`), `npx tsc --noEmit` clean.

Fixed (each has a regression test; 6 mutations of the fixes were all detected):
1. Admin routes had NO auth -> token + Admin role read from the DB (a token that only CLAIMS Admin is refused).
2. Hard-coded JWT fallback secret -> `JWT_SECRET` required (>=16 chars); the old public value is refused; `.env.example` no longer ships it.
3. Login bypass: if bcrypt threw on a malformed seed hash, any password was accepted -> removed.
4. Google login trusted a client-sent e-mail/google_id and matched on username (account takeover) -> needs a Google `id_token` verified with Google and matched only on `google_id`. Disabled (501) until `GOOGLE_CLIENT_ID` is set.
5. `PUT /auth/update` let a user set their own points, streak and account_type (even 'Admin') -> only phone; account_type Free<->Pro only with `ENABLE_TIER_TOGGLE=true`; Admin never settable; admins are made only by `npm run create-admin`.
6. No ownership checks: anyone could answer/submit/hint on other users' attempts, and reset the free hint quota with an invented attempt id -> all attempt endpoints are own-attempt only (404 otherwise); tier read from DB, not the token.
7. Re-submitting an attempt farmed points -> first submit wins (409 after).
8. No timer on the server -> answers refused after duration + 30 s; refused after submit; question must belong to the quiz; option must be A-D.
9. FAKE DATA: leaderboard, certificates, analytics, quiz counts and admin upload used an in-memory mock even with PostgreSQL -> all rewritten as SQL on the real tables; upload-quiz writes the DB (validated, one transaction).
10. Silent fallback to the mock DB on any error -> removed; DB failure is a hard error at start-up and a clean 500 per request.
11. CORS open to all -> allow-list `CORS_ORIGINS`; error messages no longer leak internals; login/register rate limit (`AUTH_RATE_MAX`); input validation (username/password/phone/ids).
12. Migration `001_hardening.sql`: unique (attempt_id, question_id) + indexes.

## Batch 5 (2026-11-09): question-bank import, DONE (partial by necessity: see numbers)
Sources found: `database/DBMS/BANK EXAMS/Simplification/Part 1` has 57 quiz PDFs + 5 bundle PDFs + `Json file/Simplification .json` (same as `frontend/src/simplification.json`). All other exam folders (TNPSC, SSC, RRB, TET, ...) are EMPTY.
Findings about the sources: (1) the JSON is NOT a real bank: 55 of its 62 "questions" are placeholders ("Sample Simplication Question for Quiz N?", options 10/20/30/40, key A) and the 7 real ones were hand-edited (Quiz 1 question 4 has different options than the PDF). It was NOT imported. (2) The PDFs are Smartkeeda quiz sets (their name, URL and "Join us" footers are in the files): third-party commercial content, see the licensing note below. (3) In the PDFs fractions, roots, exponents and mixed numbers are images or flattened into digit runs, so most questions cannot be read back reliably (extraction is not OCR).
Pipeline (`database/import/`): `extract_pdfs.py` (pypdf; 57 PDFs -> 540 question blocks; 3 PDFs (32, 33, 40) gave no readable questions) -> `verify.py` (independent exact-fraction calculator, NO eval; substitutes every option into equations; the PDF key is not trusted) -> `verified.json` + `report.json` + `REPORT.md`. Result of the 540 candidates: **86 VERIFIED (41 quizzes)**, 192 BAD_TEXT (lost fractions/exponents), 87 DISAGREE (damaged text), 65 UNCONFIRMED (the PDF's own explanation does not repeat the question exactly), 53 PARSE, 34 BAD_OPTIONS, 22 E_UNPROVEN, 1 DUPLICATE. SUSPECT_KEY (a wrong key in the PDF proven by calculation AND the PDF's own explanation): 0. So no wrong answer keys were found in what could be read.
Safeguards found by testing the verifier itself: (a) a damaged question whose plain remainder still matched the key ("6 - 5 + 2 = ? + 6 - 5", real question has mixed fractions) was first accepted -> new rule: the PDF explanation must repeat the question exactly and end at the chosen option's value; (b) "None of these" is also what damaged questions look like -> accepted only when the explanation reaches the same value; (c) option "3 7" (a flattened fraction 3/7) was read as 37 -> a space is allowed only after a sign. `test_verify.py` (17 tests): solver cases, rejection cases, the real false positive as a regression, a SECOND oracle (Python evaluator on exact fractions) agreeing on all 86 imported questions, negative control (every wrong key of every imported question is rejected); 3 mutations detected. The imported explanations are generated from our verified calculation (the PDF explanations contain flattened fractions and are kept only as `source_explanation`).
App changes: options **A-E** (E optional; many papers have five options): importer service `backend/src/modules/admin/importQuizzes.ts` (validation names the quiz/question, one transaction, idempotent with skipExisting), admin upload uses it, `npm run import:bank` loads `verified.json` into the DATABASE_URL database (safe to re-run), answering a letter the question does not have is refused, frontend exam room and result review show every option. Real-database finding: the PostgreSQL database MUST be UTF8 (the test cluster defaulted to WIN1252 on Windows and could not store the root sign): `schema.sql` now says so, the test cluster uses UTF8.
Health checks: python `unittest test_verify` 17/17; `npm test` (pg-mem) **67/67**; `npm run test:pg` (real PostgreSQL 18.6) **75/75**; e2e **50/50** on real PostgreSQL with the bank loaded (`E2E_BANK=1` on `dev:test-server` and on the run; group K: 41+1 quizzes listed, a five-option quiz played with the hints, E chosen, 5/5, review shows E); `tsc` clean (backend + frontend), build ok.

Nothing was loaded into any persistent database (there is none yet): `import:bank` is opt-in.
